# 코드 주석 규칙

이 프로젝트에서 주석을 쓰거나 고칠 때 아래를 지킨다.

## 1. 자립형 주석은 KDoc 블록 스타일로

선언(클래스·함수·프로퍼티) 위, 또는 코드 블록 위에 붙는 "그 줄만 차지하는" 설명 주석은
`//` 가 아니라 KDoc 블록으로 쓴다.

```kotlin
/**
 * ...
 */
```

- 코드 오른편에 붙는 **트레일링 인라인 주석**(`foo() // 이유`)은 그대로 `//` 로 둔다.
- `@Composable` 함수 본문 안의 지역 `val`·이펙트 위에 붙는 설명도 자립형이면 KDoc 으로.

## 2. 첫 줄은 한 줄 요약, 그다음은 리스트

- 첫 줄: 이 대상이 무엇인지 한 문장으로.
- 이후: 세부 사항은 `-` 불릿 리스트로 나열. 산문 문단으로 늘어놓지 않는다.

```kotlin
/**
 * 다음에 포커스를 줄 항목의 id.
 *
 * - 분할/병합이 세팅하고, UI 가 포커스를 준 뒤 clearPendingFocus() 로 되돌린다.
 * - null 이면 대상 없음.
 * - 연타 시 최신 id 로 덮여 마지막 항목만 남는다.
 */
```

## 3. `[링크]` / `` `코드` `` 뒤 한글 조사는 붙여 쓴다

`[SomeRef]` 나 `` `someCode` `` 를 한글 명사라고 생각하고, 뒤따르는 조사를 자연스럽게 붙인다.

- `[items]` 를 "오렌지" 라고 치면 → `[items]를`, `[items]는`, `[items]가`, `[items]에`, `[items]의` (O)
- `` `null` `` 도 마찬가지 → `` `null`이면 ``, `` `null`을 `` (O) / `` `null` 이면 `` (X)
- `[items] 를`, `` `null` 이면 `` 처럼 띄우지 않는다 (X) — "오렌지 는" 은 어색하니까.
- 무조건 붙이는 건 아니다. 뒤에 **독립된 단어**가 오면 띄운다: `[items] 목록`, `` `SENTINEL` 문자 ``.

```kotlin
/**
 * onValueChange 진입점.
 *
 * - `SENTINEL`만 사라졌다면 [mergeIntoPrevious]로 넘긴다.
 * - 개행이 있으면 [splitByNewlines]가 처리한다.
 */
```

## 4. 번역체 말고 자연스러운 한국어로

영어를 직역한 듯한 문장을 쓰지 않는다.

- 불필요한 "~에 대해", "~에 의해", "~을 위한", "~하는 것", 이중 피동("~되어진다")을 줄인다.
- 능동태·짧은 문장·평서형 종결("~한다")로 쓴다.
- 예: "포커스를 주기 위한 핸들" → "포커스를 주는 핸들" / "X에 대해 검사한다" → "X를 검사한다"
